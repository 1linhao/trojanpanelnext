# 领域文档约定

本仓库采用 single-context 领域文档布局。所有工程 Agent 在探索代码或领取工单前必须读取：

- 根目录 `CONTEXT.md`：规范领域词汇。
- `docs/adr/`：与当前工作相关的架构决策。

若文件不存在，继续工作即可；只有术语或难以逆转的决策真正确定后，才通过 `/domain-modeling` 创建或更新。

## 使用规范词汇

工单标题、规格、测试名称、代码命名和评审结论涉及领域概念时，必须使用 `CONTEXT.md` 定义的术语，不得重新引入词汇表明确要求避免的同义词。通用技术词不进入领域词汇表。

## 处理 ADR 冲突

实现方案与现有 ADR 冲突时不得静默覆盖。必须在工单中明确指出：

> 与 ADR-NNNN（标题）冲突；建议重新打开该决策，因为……

在新决策确认并记录前，不得把冲突方案视为已获批准。
