### 证据

Go 全量测试、关键包 race 测试、Go vet、amd64 / arm64 编译、Bash 语法与 ShellCheck、安装器 CLI 与 PKI 保留测试、双语 README 检查、文档站构建，以及两台 VPS 的证书替换、客户端临期、Node 离线、CA 切换和宽限期退休模拟。

### 已修复的问题

- 历史 CA 未设置 KeyUsage 被严格校验拒绝：兼容有效历史 CA，新增回归测试，新安装明确声明 KeyUsage。
- NaiveProxy 原重启函数重写空配置、旧进程退出回调可能删除替代进程：保存完整运行配置、等待退出、按进程身份清理，不删除重试配置。
- 重装时旧引导 CA 覆盖已轮换信任：保留运行 CA，并同步公开引导副本。
- CA 退休时从旧备份恢复的节点无法直接接受单 CA：先恢复双 CA，再用新客户端分发单 CA。
- 过期旧 CA 导致整个信任列表失效：只加入当前有效的 CA，仍严格拒绝非 CA、非法 PEM 和私钥内容。
- 证书与私钥分文件更新可能产生不一致身份：客户端读取不可变 generation，状态和兼容导出使用原子替换。
- CA 临期导致反复签发无法延长有效期的客户端：CA 到期上限相同的身份不重复签发。
- 构建缓存 README 和文档站生成目录影响仓库检查：排除构建缓存，忽略文档站构建输出。
