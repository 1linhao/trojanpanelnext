# 证书自动维护（v0.1.0-rc.5）

## 实现

Web / Node 的公网域名证书由独立 Caddy 管理。Node Agent 每分钟校验磁盘证书和私钥，并探测 NaiveProxy 实际提供的证书；发生变化时保存包含用户信息的运行配置，进行启动前校验，等待旧进程退出后启动新实例。该过程允许短暂断开连接。无效证书不会触发停机，失败会在下一次检查时重试，配置保持 0600。

Web API 是内部 mTLS 签发方。安装器挂载完整的 PKI 目录到 API；程序首次启动导入已有身份，用不可变 generation 保存证书和密钥，通过持久化 state.json 切换身份。文件采用原子替换及 fsync，独占文件锁阻止同目录多进程签发。客户端在每次握手时从一个完整 generation 读取证书和密钥。

每 5 分钟检查：客户端证书剩余 90 天时重新签发，有效期最多 825 天且不超过 CA；CA 剩余 365 天时生成新 CA 及待用客户端。通过已认证的 mTLS RPC 分发新旧公开 CA，所有登记的 mTLS Node（包括没有代理实例的 Node）确认后，才能切换新客户端身份。任何离线节点或旧版未支持 RPC 的节点都会阻止推进。

切换后至少保留旧身份 24 小时。清理前再次分发双 CA，帮助从旧备份恢复的节点重新取得新信任，然后分发单独的新 CA；全部确认后才清理旧 generation 的私钥。Node 在每个新握手时加载 CA 文件，更新 RPC 同时刷新引导 CA 副本；安装器重装时保留运行中的最新 CA。长期离线导致旧 CA 已到期的节点仍需人工重新引导信任。

## 升级

先升级所有 Node，再升级 Web。把现有 YAML 中的产品镜像标签更新为 0.1.0-rc.5，使用同版本安装器执行 install --config ... --force，使证书目录挂载与环境配置一并更新。新节点必须使用 Web 当前公开 CA 文件并登记到面板。完整备份 Web 的 PKI 目录，包括 state.json、generations 和符号链接；CA 私钥不复制到 Node。

旧安装器通过 OpenSSL 生成的 CA 没有显式 KeyUsage。导入支持这种有效的历史证书；新 CA 明确设置 CA 基础约束及证书签发用途。Node 信任列表中的过期旧 CA 不会阻断仍有效的新 CA。

## 验证

- Go 全量测试通过；PKI、mTLS 动态信任、NaiveProxy 配置快照与进程管理的 race 测试通过。
- 覆盖客户端续签、不必要的重复续签、CA 分发失败、进程重启恢复轮换、旧身份回退及退休私钥清理。
- 覆盖旧 CA 无 KeyUsage、未认证信任更新、移除调用方 CA、非法 PEM、过期旧 CA 与有效新 CA 并存。
- 两台测试 VPS 保留 rc.4 数据升级，公网 HTTPS、Web 到 Node mTLS、Xray / NaiveProxy / Hysteria2 状态正常。
- NaiveProxy 替换证书并恢复公网证书，两次均自动重启，运行配置及用户信息一致。
- 将 VPS 的客户端证书重新签为 30 天有效期，API 启动后自动续签，CA 保持不变。
- 将测试 CA 缩短至 180 天，并关闭 Node；轮换保持 pending。恢复 Node 后完成分发和客户端身份切换，mTLS 正常。
- 将持久化宽限期起始时间调整到 25 小时前，验证旧 CA 退休及私钥清理。该步骤模拟时间推进，并未真实等待 24 小时。
