# 外部入口实现契约

适用范围：`tls_mode: external` 兼容模式，以及未来 EntryController 的 `external` Adapter。完整的
模块边界、状态机与迁移设计见 [EntryController 方案](entry-controller/方案设计.md)。

## 1. 当前状态

当前安装器能校验外部证书、复制托管副本、停止安装器拥有的 Caddy、启动 Web/Node 服务并写出
人类可读摘要；Node Agent 会维护 `routes.json`。EntryController、external driver protocol v1、
ObservedState journal 与自动回滚已经实现；宿主系统仍须安装合规的 external driver，并负责证书续订
及 consumer hook，才能形成完整的自动续订闭环。

## 2. 分层入口模型

### Web 主控

外部入口拥有 Web 的 80/443、HTTP-01、证书续订与 TLS 终止，并把请求代理到回环地址上的 Panel
UI。UI 自己把 `/api` 转到 Panel API。数据库、Redis 与 Panel API 不应直接暴露公网。

### Node Agent

Node 不默认经过统一 L4 入口：

- Xray、NaiveProxy、Hysteria2 直接监听各自的公网 TCP/UDP 协议端口；
- 内核使用 `/tpdata/trojan-panel-core/cert` 中的证书并自行终止 TLS；
- 宿主入口只负责 HTTP-01，以及明确需要的明文 HTTP 伪装站 fallback；
- `routes.json` 只用于观测、端口/防火墙检查、443 冲突检查和 fallback 渲染；
- 不得默认由它生成 nginx `stream` TCP/UDP 转发规则。

这意味着同机 Web 入口已占用 443 时，Node 内核不能再选择 443。未来若要单 443、SNI 分流或 UDP
复用，必须作为额外 `stream.*` 能力单独设计和验收，不能暗中改变 M4 基线。

## 3. 服务与防火墙

| 服务 | 预期范围 | 说明 |
| --- | --- | --- |
| Panel UI | 回环地址 | external Web 入口的 upstream |
| Panel API | 本机 | UI 的 `/api` upstream |
| Core gRPC | 仅 Web 主控来源 | 控制面到 Node Agent |
| Core API | 仅本机/内核 | Hysteria2 认证回调等内部调用 |
| Hysteria2 traffic stats | 仅本机/授权运维 | 当前实现可能不是回环监听，必须由防火墙阻断公网 |
| Kernel protocol port | 按节点声明开放 | 直接 TCP/UDP 公网入口，TLS 在内核终止 |
| Plain fallback | 回环或本机 | 仅供已经解密的内核 fallback，不能启用 TLS |

配置里的 `bind_address` 当前只控制 Web UI，不控制 Core、gRPC 或内核监听。不能把它当成防火墙。

## 4. 证书契约

Node 的 `tls_cert_dir` 必须含有效、未过期、覆盖节点域名且与私钥匹配的证书。识别顺序是：

1. 显式 `tls_cert_file` + `tls_key_file`；
2. `fullchain.pem` + `privkey.pem`；
3. 唯一的同词干 `.crt` + `.key`。

安装器把材料原子复制为：

```text
/tpdata/trojan-panel-core/cert/fullchain.pem
/tpdata/trojan-panel-core/cert/privkey.pem
```

私钥目录为 0700、私钥为 0600、证书为 0644。内核只读托管副本，不直接读取 certd/certbot 的源
目录。Core 启动时会把已有 Xray、NaiveProxy 和 Hysteria2 配置中的旧证书路径同步为当前路径。

续订只能有一个 timer 所有者。最终 external driver 在证书指纹变化后必须调用同一个 reconcile：

1. 校验并原子更新托管副本；
2. 更新持久化的证书 generation；
3. 重启读取证书的内核消费者；
4. 刷新 `routes.json` 并记录 reload 结果。

当前兼容实现没有自动 hook。过渡期需在外部证书续订后重新运行 installer 并重启内核；这项人工
步骤必须在上线清单中显式记录，不能用一个不会被调用的 `reload_command` 掩盖。

## 5. `routes.json` 观测契约

路径：

```text
/tpdata/trojan-panel-core/external/routes.json
```

Node Agent 启动、节点新增和节点删除后原子重写该文件。其顶层字段包括 schema 版本、生成时间、
Core 版本、证书路径、伪装站根目录和 `routes` 数组。

| 路由字段 | 含义 |
| --- | --- |
| `kernel` / `protocol` | 内核与协议 |
| `port` | 直接协议监听端口；用于防火墙与冲突检查 |
| `api_port` | 内核管理端口；不得对公网开放 |
| `network` | `tcp`、`ws`、`grpc`、`udp` 等观测值 |
| `security` | `none`、`tls`、`reality` |
| `sni` | 域名观测值，不代表 external 必须按 SNI 转发 |
| `ws_path` / `grpc_service_name` | 内核传输配置观测值 |
| `fallback_port` | 内核解密后转发明文 HTTP 的目标端口；0 表示没有 |
| `external_fallback_listener_required` | external ingress 是否必须提供明文 fallback |
| `tls_terminated_by_kernel` | 是否由内核自己终止 TLS |

消费者必须忽略未知字段，并拒绝不支持的 `schema_version`。不要监听或转发 `api_port`。

只有 `external_fallback_listener_required: true` 才创建 fallback：监听应与内核配置完全一致，服务
`/tpdata/web`，使用明文 HTTP。若 HTTP-01 正在占用 80，应为节点选择不冲突的回落目标，例如
`127.0.0.1:8443`，并在该端口提供同一站点。

## 6. external driver 协议

EntryController 通过配置中的绝对路径调用 driver。driver 文件必须由 root 拥有且 group/world 不可
写；EntrySpec 以 0600 文件传入，stdout 只输出与 ObservedState schema 兼容的 JSON。

```text
provider probe     --spec <file>
provider prepare   --spec <file>
provider activate  --spec <file>
provider verify    --spec <file>
provider rollback  --spec <file>
provider remove    --spec <file> [--purge]
```

`probe` 必须显式返回能力，尤其是 `certificate.material`、`certificate.renew`、Node 所需的
`certificate.notify`、`lifecycle.prepare` 和 `lifecycle.rollback`。缺少 rollback 的 driver
只允许生成需要人工接管的 plan，不能执行自动切换。
外部资源的 `owner` 必须记为 `external`；Controller 不直接删除 nginx、certd、证书目录或外部 timer。

## 7. 迁移与失败恢复

Caddy → external 的安全顺序是：先校验可迁移证书和 driver 能力，准备候选而不抢 80/443，记录旧
Caddy 快照与回滚动作，再停止旧入口、激活和验证新入口。失败时先停候选，再恢复旧 Caddy。反向
切换使用同一套 journal。证书数据默认保留，只有显式 purge 且确认无其它 consumer 才能删除。

当前兼容路径只具备“删除 Caddy 失败则中止”的 fail-closed 行为，没有完整 journal；首次真实迁移
前必须补齐并验证回滚，不能把本地 fake 测试视为实机证明。

## 8. 最小实机验收

- DNS A/AAAA 指向正确，80/443 只有计划中的入口进程占用；
- HTTP-01 首签与续订成功，且机器上只有一个续订 timer；
- nginx 候选配置检查失败不会覆盖活动配置，reload 失败能恢复旧入口；
- Web HTTPS、静态资源、登录与 `/api` upstream 正常；
- Xray、NaiveProxy、Hysteria2 各选一个客户端做真实 TCP/UDP 拨测；
- Node 协议端口直接可达，TLS 证书正确，未产生默认 L4 转发；
- fallback 命中时返回明文伪装站，未要求 fallback 的路由不创建监听；
- Core API、gRPC、traffic stats、数据库与 Redis 的防火墙范围正确；
- 证书续订后托管副本、内核进程和状态 generation 一致；
- Caddy ↔ external 切换在激活失败、验证失败和进程中断后均可恢复。
