## Redis 持久化权限与登录超时修复审查

### 复现与根因

- 用户报告登录提示 `timeout of 5000ms exceeded`。公网登录复现超过 5 秒，本机 API 请求也超时；静态首页正常，独立数据库查询正常。
- Redis 的 `/data` 对应宿主机目录为 root:root、0700，而实际服务 UID/GID 为 999:999。RDB 保存持续报 Permission denied，`rdb_last_bgsave_status:err`，随后 Redis 拒绝 PING 和写操作，返回 MISCONF。
- 安装器对已绑定到目标目录、尚为空的数据目录再次执行迁移：`cp -a 临时目录/. 目标目录/` 把 mktemp 的 root 所有者和 0700 属性复制到了正在运行的 Redis 数据目录。
- API/Node Redis 池的 Dial 遇到错误直接 panic，绕过 Redigo 归还连接名额的路径；名额耗尽后 Wait=true 导致请求一直等待。

### 修复与审查范围

- 已映射到相同宿主机路径的数据目录直接跳过迁移；旧容器迁移仅复制目录内容（含隐藏文件），保留目标目录本身的所有者和权限。
- 安装器根据运行中的 Redis UID/GID 修复其数据目录，不重启 Redis、不丢弃内存会话。
- API 与 Node 的 Redis Dial/PING 错误正常返回，关闭失败连接，使连接池归还名额；连接、读、写增加 3 秒超时。前端默认 5 秒没有放宽。
- 版本升级为 `0.1.0-rc.7`，脚本、模板、文档和镜像标签继续绑定，保留 rc.6 标签。

### 验证证据

- 修复前：目录回归测试失败，真实 Redigo TCP 夹具的 MISCONF、意外 PING 响应、连接拒绝均触发 panic。
- 修复后：上述测试通过；连续失败连接不保留名额，Redis 恢复后同一个池无需重启即可读到数据。API/Node 新测试的 race 检查通过。
- API 全部 Go 测试与 go vet、Node 全部 Go 测试通过；四组安装器测试、ShellCheck、双语 README、rc.7 版本绑定和 diff 检查通过。
