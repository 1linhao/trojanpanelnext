## 需求概述

操作机统一部署流程需要让新安装的 Web、Node 或 combined 目标在宿主机上只使用一个专属业务数据根目录，并提供安全、可预期的卸载：自动删除本项目受管容器和可安全删除的镜像，是否彻底删除业务数据由操作者显式选择。本增量不授权清理旧版散落数据或任意第三方资源。

## 功能需求

### 2026-09-28 用户确认：Node 撤销与卸载

- 独立 Node VPS 卸载前，先在 Web VPS 撤销对应 Node 身份；Node 本地卸载消费可验证的撤销结果。
- Node VPS 突然掉线、失联或销毁时，Web 必须能独立执行强制撤销，不等待 Node 响应。复用现有 `force-evict`，验证数据库与 Redis 权限、控制授权回收，重复操作幂等，其他 Node 不受影响。
- 已销毁 VPS 只需完成 Web 侧强制撤销，不要求再在该 VPS 执行本地卸载。Web 撤销失败或结果不确定时不得宣称成功。
- 撤销结果的证明载体、信任绑定及失败恢复方案由 #46 落实；不把 Web 管理员或全局数据层密码放到 Node VPS。

### P0 - 必须实现

- [ ] 新部署的宿主业务数据固定归入 `/tpdata/trojanpanelnext`，Web、Node、combined 的数据库、配置、凭据、证书、入口状态、日志及安装器持久资产均不得再写入同级分散业务目录；容器内已有固定路径可与宿主路径不同。
- [ ] `remove` 自动停止并删除归属可证明的本项目容器，并清理不被其他容器使用的本项目镜像；共享镜像或仍有其他角色使用的镜像不得强删，结果逐项报告。
- [ ] 普通 `remove` 保留业务数据。只有显式 `--purge-data` 且该宿主最后一个受管角色已卸载，才可在归属与路径安全校验后彻底删除 `/tpdata/trojanpanelnext`。combined 卸载单个角色时不能删除仍存角色需要的共享数据。
- [ ] `deploy` 遇到旧版、外来或归属不明的容器、镜像、数据目录及端口冲突时停止并列明对象，不自动清理。
- [ ] 旧版散落在 `/tpdata` 的数据不迁移、不自动删除；操作者自行处理。新版脚本不得因旧数据存在而扩大删除范围。
- [ ] 卸载与彻底清除只由目标 VPS 上的底层安装器 `remove` 提供；操作机的统一脚本本轮仍只承担 `init/check/deploy`，不新增跨 VPS `remove`。

## 非功能需求与约束

- 所有删除操作均须基于精确资源身份和归属证据；不得使用全局 Docker prune、按宽泛名称或未校验路径递归删除。
- 删除前完成计划与归属预检；失败保留可诊断状态，重跑不误删其他角色或外部服务。
- 入口续期单元、运行脚本等宿主业务根外的受管系统资源要按其原有所有权契约处理，不把 `/etc`、`/usr/local` 或外部证书目录纳入业务根递归删除。
- 真实 VPS 清理仍需就具体主机和目录另行人工批准；本需求确认的是产品脚本语义，不是立即执行清理。

## 验收标准

- Given 全新隔离宿主，When 分别安装 Web、Node、combined，Then 受管宿主业务数据均位于 `/tpdata/trojanpanelnext` 内；容器仍只获得各自必要的挂载。
- Given 已安装部署，When 普通 `remove`，Then 仅受管容器和无人使用的受管镜像被清理，数据根及其内容保持不变。
- Given combined 的 Web 和 Node 均在运行，When 只卸载一个角色并传 `--purge-data`，Then 不删除共享业务根、另一角色与其健康状态保持不变。
- Given 最后一个受管角色已卸载且显式传 `--purge-data`，When 完成归属及路径校验，Then 仅 `/tpdata/trojanpanelnext` 业务根被彻底清理；未知归属、符号链接、路径漂移或外部容器引用使操作安全失败。
- Given 存在旧版或外来资源，When 执行 `deploy`，Then 在副作用前停止并报告冲突，不自动删容器、镜像或旧布局数据。
