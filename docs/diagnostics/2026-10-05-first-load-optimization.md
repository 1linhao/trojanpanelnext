# 首次访问优化实施与验证

完成时间：2026-10-05 17:14（Asia/Shanghai）。站点：`trpl.lhsiteb.site`，Web 主机：`ssh web`。

## 已完成

1. 管理员上传 Logo 时，在 API 中解码和验证图片，等比缩放到 256×256 透明画布，使用 PNG 最佳压缩保存。输出保留比例和透明背景，不裁剪、不拉伸。编码成功后通过同目录临时文件原子替换，失败时保留原文件。继续支持当前 PNG 上传方式及 3MB 限制，解码前拒绝超过 4096 像素的尺寸，限制整个 multipart 请求体。
2. 默认和已有 Logo 在 API 启动时进行一次规格优化；已有 256×256 PNG 保持不变。兼容历史 `.png` 文件中实际为 JPEG 的情况。Logo 响应改为正确的 `image/png`，移除附件下载头。
3. 线上 Caddy 对首页、`/index.html` 和 `/static/*` 启用 zstd/gzip；没有对登录或管理 API 加缓存或压缩规则。安装脚本中有邮箱、无邮箱两个 Caddy 配置分支同步修改。
4. 修正 Logo 上传路径的 Nginx 请求体限制，使代理允许 3MB 文件及 multipart 开销，其余路径保持原限制。线上与安装模板同步修改。

## 实测结果

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 四份入口 JS/CSS 浏览器实际传输体积 | 445,880 B | 150,762 B（zstd，降低 66.2%） |
| 同四份资源强制 gzip 的传输体积 | 445,880 B | 149,198 B |
| Logo | 460,503 B，1153×1080 JPEG | 93,297 B，256×256 PNG（降低 79.7%） |
| 先仅启用资源压缩，两次无缓存登录表单可见 | 基准 7.888 秒；重试 38.411 秒 | 3.054、3.139 秒 |
| 两项都上线后，三次无缓存登录表单可见 | 同上 | 4.700、2.618、7.745 秒 |
| 两项都上线后，三次首次内容绘制 FCP | 基准 8.084 秒；重试 38.448 秒 | 4.656、2.692、7.880 秒 |

体积减少是确定的，时序仍受跨境线路波动影响。第三次复测中，入口 JS 压缩后约 59 KB，下载仍耗时约 5.8 秒，其中接收响应体约 5.2 秒。本次优化没有消除跨境传输波动，也没有达到每次都低于 5 秒的诊断阈值。两项用户指定的待办已实施完成，不能将它们表述为所有境内线路加载问题彻底解决。

## 部署与回滚

线上 API 使用从现有 rc.13 基础镜像构建的本地补丁镜像 `trojanpanelnext-api:logo-opt-20261005`，容器仍名为 `trojan-panel`，重启策略仍为 `always`。本次没有发布新 GitHub Release 或覆盖官方镜像标签；未来升级需使用包含这些源码改动的正式镜像，强制重装旧 rc.13 官方镜像会恢复旧上传逻辑。

Web 主机备份目录为 `/tpdata/custom/first-load-optimization-20261005`（权限 0700），保留原 Caddyfile、Nginx 配置、Logo 和容器配置。容器配置备份含恢复所需的环境变量，权限为 0600，未输出凭据。

原 API 容器保留为 `trojan-panel-before-logo-opt-20261005`，处于停止状态、重启策略设为 `no`，防止宿主机重启时与新容器争抢端口。原官方镜像仍在。回滚 API 时需停止新容器、恢复原容器名称和原 Logo，并恢复原重启策略 `always`。Caddy/Nginx 使用文件绑定挂载，恢复配置时应原位写回原文件，分别校验后热加载，避免替换 inode 导致容器读到旧配置。
