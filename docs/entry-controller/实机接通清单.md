# EntryController 实机接通清单

本清单是“允许真实 Adapter 副作用”的门槛。本地 fake 通过不能替代这些证据。

## 通用前置

- 保存现有入口配置、证书、timer、监听和防火墙快照，确认恢复命令可用。
- 使用 root 所有、0600、非 symlink 的 EntrySpec；核对 deployment、revision、domain 和 purpose。
- external driver 使用绝对路径、root 所有、非 symlink、group/world 不可写；记录 SHA-256。
- 核对 80/443 及 Node TCP/UDP 协议端口的当前 owner，不在所有权不明时 adoption。
- 核对同一域名只有一个证书续订单写者；确认 CA rate limit 与测试/生产目录隔离。

## External / VPS Factory adoption

- 对 Web 分别执行并保存 `probe/prepare/activate/verify/rollback/remove` 的 protocol v1 JSON。
- 对 Node 重复上述动作，确认 driver 不创建动态 nginx stream，不代理内核 direct 端口。
- 验证 Web 80→HTTPS、443 TLS、Host/X-Forwarded-*、loopback UI upstream。
- 验证 Node HTTP-01 和声明的明文 fallback；未声明 fallback 时不得创建额外 listener。
- 验证证书路径、域名、私钥匹配、指纹、notAfter、generation 和唯一 renewal owner。
- 强制一次受控的证书 changed 流程，确认 Node 托管副本原子替换和消费者 reload/restart 状态。
- 在 prepare、activate、verify 各故障点注入失败；验证旧入口恢复、journal 与 driver identity 未漂移。
- 在进程写入 `activating` 后中断，再运行同 revision；确认先 rollback 再 prepare。
- 替换 driver 内容但保留路径，确认未完成 journal 与 remove 都返回 ownership conflict。
- 连续执行两次 remove；第二次必须是 removed/unchanged，且不删除共享证书或其它 deployment 资源。

## nginx-certbot（接通前）

- 先把当前纯计划中的 argv 逐项转成受控执行，不使用 shell 拼接。
- 在隔离 candidate 路径写配置，执行真实 `nginx -t` 后才允许原子替换和 reload。
- Web 验证 nginx 独占所需 80/443；Node 只允许 80 和明确的 loopback fallback。
- 使用 certbot staging 完成首次签发、续订 dry-run、deploy hook 与失败可观测性，再切生产 CA。
- 模拟 nginx reload 失败，确认活动配置、进程和证书 lineage 都回到旧版本。
- 验证 systemd timer 唯一、锁互斥、重复 reconcile/remove 幂等，重启后 journal 可恢复。

## 网络与完成证据

- 从公网与授权主控分别拨测 TCP/UDP；确认数据库、Redis、gRPC、traffic stats 等内部端口不可公网达。
- 创建至少一个 Xray、NaiveProxy、Hysteria2 测试节点，核对 direct listener、证书路径和 routes.json。
- 重启宿主后复测入口、timer、防火墙、journal status 和 driver probe。
- 只有上述证据全部留档，才把相应 Adapter 的真实 mutation 开关设为 enabled。
