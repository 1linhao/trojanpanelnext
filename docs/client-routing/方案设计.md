### 客户端节点组分流

系统管理员在「系统配置 → 节点组分流」选择服务器和节点，定义组名、手选或自动测速方式，按优先级添加精确域名、域名后缀和 IPv4/IPv6 地址或网段规则。每组只引用同一服务器的节点 ID，可跨服务器定义多个组。单独配置未匹配流量的默认策略，以及授权或兼容性筛选后无可用成员时的拒绝或直连策略，初始空组策略为拒绝。

发布版本包含结构化基础模板（本地监听端口、TUN MTU、日志级别）、流量规则和 DNS（默认解析器及按后缀指定解析器）。服务端校验输入并生成两份不含账号凭证的可复用配置骨架。MySQL 保存输入、骨架及活动版本指针。切换与删除在同一指针行上加锁，活动版本不能删除；版本不可变，修改历史版本须复制发布。

发布后，已有 Clash.Meta default 和 sing-box tun 订阅在原地址刷新即可使用活动分流版本，停用后回到同客户端原有模板。sing-box outbound 与 URI 链接始终使用对应格式。请求按现有账号授权、节点兼容性和出站渲染结果生成实际成员，并再次检查所属服务器。自动测速由客户端原生 url-test / urltest 完成。

管理接口位于 /api/system/clientRouting，提供读取版本及候选节点、发布、恢复活动指针、停用和删除历史版本操作。管理端仅允许系统管理员。首期采用结构化共同字段生成两种客户端配置，原有按客户端编写的自由格式模板仍在「订阅模板」维护。

验证覆盖有序规则、地址标准化、跨服务器引用、账号可见成员、空组、发布历史、原有导出模式和 Web 构建。

客户端语法参考 [Mihomo 自动测速组](https://wiki.metacubex.one/en/config/proxy-groups/url-test/)、[Mihomo DNS](https://wiki.metacubex.one/en/config/dns/)、[sing-box URLTest](https://sing-box.sagernet.org/configuration/outbound/urltest/) 和 [sing-box 路由动作](https://sing-box.sagernet.org/configuration/route/rule_action/)。
